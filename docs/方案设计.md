## 1. 可行性结论

| 项目 | 结论 |
| --- | --- |
| 官方 JetBrains 插件 | **没有**。粉笔目前只提供 App / PC 客户端 / 网页版 |
| 同类先例 | VS Code 有 `Fenbi Tools`（闭源）和 `fenbi-moyu`（开源，github.com/Jolly-Xu/fenbi），原理都是「登录态 Cookie + 调 tiku.fenbi.com 接口」 |
| 网页接口 | 可用，已实测：不带 Cookie 一律返回 `401`，带 Cookie 正常返回 JSON |
| 登录方式 | 无开放 OAuth，只有手机号 / 扫码。网页登录态存放在 `.fenbi.com` 域下的 Cookie（`sess`、`persistent`、`userid`、`sid` 等，其中 `sess`/`persistent` 为 HttpOnly） |
| 插件内扫码 | **可行**。IDEA 2024.3 自带 `com.intellij.ui.jcef.JBCefCookieManager`，可读取 CEF Cookie 仓库（含 HttpOnly），无需从 JS 取 `document.cookie` |

**结论：能做，而且是完整的「登录 → 选题库 → 做题 → 判题 → 解析 → 交卷」闭环。**
主要风险不在插件开发，而在接口稳定性与账号风控（见第 10 节）。

## 2. 功能范围（v1.0）

| 功能 | 说明 | 优先级 |
| --- | --- | --- |
| 扫码登录 | Tool Window 内嵌网页，手机粉笔 App 扫码，自动抓 Cookie 并存 PasswordSafe | P0 |
| 登录态校验 / 失效重登 | 启动时静默校验，401 时引导重登，不丢练习进度 | P0 |
| 行测题库树 | 言语理解、判断推理、数量关系、资料分析、常识判断（接口返回的分类层级） | P0 |
| 组卷 | 按分类 + 题量组卷，复用粉笔「未完成练习」，中断后可续做 | P0 |
| 逐题作答 | 点击选项即提交（同粉笔 App 练习模式），即时显示对错 + 解析 | P0 |
| 交卷回写 | 调用提交接口，成绩同步到粉笔账号（App 端可见） | P0 |
| 申论试卷 | 试卷列表 → 材料 + 作答要求 → 写作 → 参考答案 | P1 |
| 错题本（本地） | 答错自动入库，支持重做；不依赖粉笔接口 | P1 |
| 练习统计（本地） | 今日题量、正确率、连续天数 | P2 |
| 快捷键呼出/隐藏 | 默认 `Ctrl+Alt+F`，可改；支持「摸鱼模式」一键切回代码 | P0 |
| 主题适配 | 跟随 IDE 深/浅色，题目 HTML 注入主题 CSS | P1 |

**明确不做**：智能批改、视频解析、课程/直播、模考排名、账号多开、自动答题脚本。
（自动答题会触发风控，也不符合「刷题学习」的初衷。）

## 4. 架构设计

```
┌─────────────────────────────────────────────────────┐
│ Tool Window (FenbiToolWindowFactory)                │
│  ├─ BankPanel      题库分类树 + 上次练习入口         │
│  ├─ QuizPanel      行测做题（题干/选项/解析）        │
│  ├─ EssayPanel     申论试卷（材料/作答/参考答案）    │
│  ├─ StatsPanel     本地统计                          │
│  └─ SettingsPanel  题量/地区/主题/快捷键/Cookie      │
├─────────────────────────────────────────────────────┤
│ Service 层（应用级，@Service）                       │
│  ├─ FenbiSession   登录态、Cookie 注入、401 拦截     │
│  ├─ FenbiApi       行测/申论接口封装 + DTO           │
│  ├─ ExerciseStore  当前组卷、答题记录、断点续做      │
│  └─ LocalStore     错题本、统计（JSON）              │
├─────────────────────────────────────────────────────┤
│ 基础设施                                            │
│  ├─ CookieLoginDialog（JCEF 网页 + 扫码 + 抓 Cookie）│
│  ├─ ApiExecutor（ProgressManager + 后台线程池）      │
│  └─ HtmlRenderer（主题 CSS 注入 + 图片代理）         │
└─────────────────────────────────────────────────────┘
```

**线程模型**：所有网络请求走 `AppExecutorUtil.getAppExecutorService()`，用 `ProgressManager.run(Task.Backgroundable)` 包一层；回调统一切回 EDT（`ApplicationManager.getApplication().invokeLater`）。EDT 上禁止阻塞。

**错误处理**：401 → 抛 `LoginExpiredException`，全局捕获后弹登录框；网络错误 → 面板内联错误条 + 重试按钮；接口结构变化 → 打日志并降级为「原始 HTML 展示」。

## 5. 登录方案（关键）

### 5.1 流程

1. 用户点「扫码登录」，弹出 `DialogWrapper`，内嵌 `JBCefBrowser` 加载 `https://www.fenbi.com/spa/tiku/xingce/categories`。
2. 用户在手机粉笔 App 扫码确认，网页跳转到已登录状态。
3. 插件每 1.5s 轮询一次 Cookie 仓库：

```java
List<JBCefCookie> cookies = JBCefCookieManager.getInstance()
        .getCookies("https://tiku.fenbi.com")
        .get(5, TimeUnit.SECONDS);

String cookieHeader = cookies.stream()
        .filter(c -> c.getDomain().endsWith("fenbi.com"))
        .map(c -> c.getName() + "=" + c.getValue())
        .collect(Collectors.joining("; "));
```

4. 用该 Cookie 调 `GET /api/xingce/categories`：
   - `200` → 登录成功，写入 `PasswordSafe`，关闭弹窗，刷新题库。
   - `401` → 继续轮询（最多 3 分钟）。
5. 兜底入口：弹窗底部「手动粘贴 Cookie」，供 JCEF 被企业策略禁用时使用。

### 5.2 为什么能拿到 HttpOnly

`JBCefCookieManager` 读取的是 CEF 的 Cookie 仓库，不经过 JS，因此 `sess` / `persistent` 这类 HttpOnly Cookie 同样可见。已在本机 IDEA 2024.3.1.1 的 `app-client.jar` 中确认存在：

- `com/intellij/ui/jcef/JBCefCookieManager.class`（`getCookies(String url)` 返回 `Future<List<JBCefCookie>>`）
- `com/intellij/ui/jcef/JBCefCookie.class`（`getName/getValue/getDomain/getPath`）

### 5.3 安全

- Cookie 只存 `PasswordSafe`（OS 凭据库加密），不落明文配置、不进日志。
- 不上传任何数据；网络请求只发往 `*.fenbi.com`。
- 「退出登录」= 删除 PasswordSafe 条目 + 清空 JCEF 存储。

## 6. 接口清单

公共参数（所有请求）：

```
app=web&kav=100&av=100&hav=100&version=3.0.0.0
Header: User-Agent: <Chrome UA>
Header: Origin / Referer: https://spa.fenbi.com/
Header: Cookie: <登录态>
```

### 6.1 行测

| 用途 | 方法 | 路径 | 关键参数 / 返回 |
| --- | --- | --- | --- |
| 分类树 | GET | `/api/xingce/categories` | `filter=keypoint`；返回 `[{id,name,count,answerCount,children}]` |
| 未完成练习 | GET | `/api/xingce/category-exercises-unfinished` | 返回 `{exerciseId,keypointIds,combineKey,sheetType}`，用于「继续上次」 |
| 用户组卷偏好 | GET | `/activity/userquiz/getUserQuestionInfo` | 返回 `questionCount / yearScope / correctRatioLow / correctRatioHigh` |
| 组卷 | POST | `/api/xingce/exercises` | form：`type=3&exerciseTimeMode=2&keypointId=&limit=&yearScope=&correctRatioLow=&correctRatioHigh=`；返回 `id` |
| 试卷详情 / 答题记录 | GET | `/api/xingce/exercises/{exerciseId}` | 返回 `userAnswers / correctCount / questionCount` |
| 题目 | GET | `/api/xingce/universal/auth/questions` | `type=0&id={exerciseId}`；返回 `questions[] / materials[]` |
| 单题提交 | POST | `/api/xingce/async/exercises/{id}/incr` | JSON 数组：`[{answer:{type:201,choice:"1"},flag:0,questionId,questionIndex,time}]` |
| 交卷 | POST | `/api/xingce/async/exercises/{id}/submit` | form：`status=3` |
| 解析 | GET | `/api/xingce/universal/auth/solutions` | `type=0&id={exerciseId}`；返回 `solutions[]`（含 `correctAnswer.answer`、`solution`） |

### 6.2 申论

| 用途 | 方法 | 路径 | 关键参数 / 返回 |
| --- | --- | --- | --- |
| 试卷标签 | GET | `/api/shenlun/subLabels` | 返回 `[{name,labelMeta:{id,paperIds[]}}]`（国考/省考/…） |
| 试卷详情 | GET | `/api/shenlun/papers/{paperId}` | 返回 `{id,name,date,topic,encodeCheckInfo}` |
| 材料 + 参考答案 | GET | `/api/shenlun/universal/auth/solutions` | `type=7&id={paperId}&checkId={encodeCheckInfo}`；返回 `materials[] / solutions[]` |

> 说明：申论无「逐题判分」，v1 只做「材料 + 作答 + 参考答案对照」，不做 AI 批改。申论接口在未登录时同样返回 401，路径真实性需登录后联调确认（已写进 M3 验收项）。

## 7. 数据模型

```java
// 行测
record Category(long id, String name, int count, int answerCount, List<Category> children) {}

record Question(long id, String content, int type, int difficulty,
                List<Accessory> accessories,   // accessories[0].options = ["A选项","B选项",...]
                List<Integer> materialIndexes, Integer material) {}

record Material(String content) {}

record UserAnswer(long questionId, int questionIndex, String choice, int time) {}

record Solution(long id, String content, String solution,
                CorrectAnswer correctAnswer, String source) {}

// 申论
record EssayPaper(long id, String name, String date, String topic,
                  String encodeCheckInfo, List<Material> materials, List<Solution> solutions) {}
```

解析字段注意：`correctAnswer` 在不同接口里键名不一致（`choice` / `answer`），DTO 用 `@SerializedName` 兼容两种。

## 8. 界面设计

详见同目录原型：`../prototype/index.html`（可点击）。

### 8.1 布局

- **右侧 Tool Window**，默认宽 520px，可拖动、可折叠。
- 顶部：标题栏（`粉笔刷题` + 刷新 / 设置 / 折叠）。
- Tab：`题库` / `错题本` / `统计` / `设置`。
- 题库页：分类列表（行测 5 类 + 申论 3 类），底部「继续上次练习」。
- 做题页：面包屑返回 + 进度条（3/10）+ 计时 + 收藏；题干区；选项区；解析区（作答后展开）；底部操作条。
- 申论页：材料区（可滚动）+ 作答要求 + 输入框（实时字数）+ 查看参考答案。

### 8.2 交互

| 动作 | 结果 |
| --- | --- |
| 点击分类 | 若有未完成练习 → 弹「继续 / 重新组卷」；否则组卷并进入第 1 题 |
| 点击选项 | 立即提交单题，选项染色（正确绿 / 错误红 + 标出正确项），展开解析 |
| `Enter` / `→` | 下一题（已作答时） |
| `1`~`4` | 快速选择 A~D |
| `Ctrl+Alt+F` | 隐藏 / 呼出面板（摸鱼模式） |
| 最后一题 | 「交卷」按钮高亮，交卷后展示成绩单 |

### 8.3 视觉

- 完全使用平台配色（`JBColor` / `UIUtil`），随 IDE 主题切换；题目 HTML 注入 CSS 变量，深色下不刺眼。
- 题干预览使用 JCEF，图片走 `https://tiku.fenbi.com` CDN，需要时加 Referer 头。
- 加载态用 `JBLoadingPanel`，避免白屏闪烁。

## 12. 风险与合规

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 粉笔接口变更 / 加签名 | 功能失效 | 接口层集中封装，一处适配；出问题只改 `FenbiApi` |
| 频繁请求触发风控 | 账号被限 | 只在用户操作时请求、请求间隔 ≥300ms、不做自动答题、不加多账号 |
| Cookie 泄露 | 账号安全 | PasswordSafe 加密存储、不写日志、不外传 |
| JCEF 被企业策略禁用 | 无法扫码 | 手动粘贴 Cookie 兜底 + 明确提示 |
| 使用条款 | 合规风险 | 仅个人学习使用；如需公开发布，先评估粉笔用户协议，建议不商业化、不上架 |
| `until-build` 限制 | 新版 IDE 装不上 | 设为 `243.*` 并在 README 说明改一行即可放宽 |

## 14. OpenClaw 联动（v0.2，已实现）

### 14.1 为什么是「插件主动问询」

OpenClaw 部署在云服务器，插件在本机 NAT 后面，云端无法入站调用插件。因此方向反过来：

```
插件 --(9:00 后每 2.5 小时)--> POST /v1/chat/completions  "生成今日计划，只输出 JSON"
     <--(JSON 计划)--------
插件 解析考点 -> 组卷 -> 通知用户点「开始」
用户 做题、交卷
插件 --> POST /v1/chat/completions  "分析这次成绩"
     <--(分析文本)--------- 显示在报告页
插件 --> POST /hooks/wake          （可选）让 OpenClaw 把反馈推到 IM
```

### 14.2 前提

- `openclaw.json` 打开 `gateway.http.endpoints.chatCompletions.enabled = true`
- 插件设置里填网关地址 + 网关 Token（+ 可选 hooks.token）
- 插件保持登录粉笔（问询时会顺带拉一次分类树，把可用考点写进提示词，提高匹配率）

### 14.3 计划与报告协议

计划（agent 输出，插件解析）：

```json
{"planId":"20261023-2130","date":"2026-10-23","deadline":"23:30",
 "items":[{"type":"逻辑填空","count":10},{"type":"资料分析","count":10}],
 "note":"资料分析多练"}
```

- `type` 为细考点，插件在分类树中递归匹配（精确 → 包含 → path 消歧）。
- 每个考点单独组卷，串行执行；一项结束点「下一项」。

报告（插件回传）：

```json
{"planId":"...","finishedAt":"...","elapsedSeconds":1830,"total":20,"correct":14,"accuracy":0.7,
 "items":[{"type":"逻辑填空","path":"言语理解与表达 / 逻辑填空","total":10,"correct":7,
           "seconds":900,"wrong":[{"questionId":123,"stem":"…","your":"B","correct":"C"}]}]}
```

### 14.4 调度规则

- 每天 `planStartHour`（默认 9）到次日 01:00 之间轮询；
- 间隔 `planInterval`（默认 150 分钟 / 2.5 小时），IDE 启动时若在窗口内会立刻问一次；
- 当天已拿到计划（无论是否开始）就停止问询，次日恢复；
- 手动「立即问询」不受时间窗口限制。

### 14.5 已知边界

- 计划里的考点若在粉笔分类树里不存在，会被跳过并在状态栏提示；
- 一次组卷只能一个考点，无法生成跨考点混合卷；
- 分析质量取决于 OpenClaw 侧的记忆/提示词，插件只负责把结构化数据送过去。
